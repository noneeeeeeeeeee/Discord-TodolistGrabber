# Autoplay V2 Runbook

This runbook documents how to operate and troubleshoot the Autoplay Engine V2 stack. It assumes the codebase has been updated to use the new engine introduced in `modules/music/Autoplay_Engine/v2/`.

## 1. Components & Responsibilities

- `AutoplayEngineV2`: orchestrates Last.fm lookups, Gemini enrichment, collaborative blending, and Pomice resolution.
- `GeminiService`: manages Gemini API keys, batching, quota tracking, and classification calls.
- `CacheManager`: persists mappings (`mappings_v2.json`), enrichment payloads, parsed titles, mood vectors, and collaborative snapshots under `cache/music/`.
- `FeedbackManager`: records anonymised play/skip/like events, manages guild/user opt-outs, and streams JSONL telemetry (`cache/music/telemetry/events.jsonl`).
- `CollaborativeMatrix`: hydrates collaborative embeddings (generated by `scripts/cf_train.py`) and blends them into candidate scoring.
- `TrackResolver`: rebuilds Pomice `Track` objects from cached mappings or live searches.

## 2. Prerequisites & Configuration

1. **Environment variables**

   - `LASTFM_API_KEY` – required for all recommendation fetches.
   - `GeminiApiKeys` (comma-separated) or `GEMINI_API_KEY` – required for parsing, enrichment, and mood vectors.
   - Optional: `AUTOPLAY_HASH_SALT` – if omitted, a salt is generated and stored at `cache/music/telemetry/salt.txt`.

2. **Selecting the engine**

   - Globally configured in `modules/music/Autoplay_Engine/config.py` via `AUTOPLAY_VERSION` (default `"v2"`).
   - On failure to initialise V2 (missing key, import error) the config automatically logs the exception and falls back to the legacy V1 engine.

3. **Gemini quotas**

   - Free-tier quotas are tracked in `cache/music/gemini_usage.json` with automatic daily rollover.
   - The service enforces batching (`ENRICHMENT_BATCH_MAX`) and cooldown windows; keep API usage under 500 requests per day.

4. **Pomice / Lavalink**
   - Ensure the Lavalink node settings (`LAVALINK_HOST`, `PORT`, `PASSWORD`, `SECURE`) remain valid. V2 uses the same connection manager as V1.

## 3. Daily Operations

- **Startup validation**

  - Watch for `AutoplayEngine: Using version V2` and `Last.fm autoplay V2 is READY` in the bot logs.
  - Absence of these lines indicates V2 failed to load; see Troubleshooting.

- **Runtime status**

  - Call the existing stats surface (e.g. slash command or console helper wired to `AutoplayEngineV2.get_stats()`). The payload includes:
    - Gemini availability and quota remaining.
    - Collaborative matrix snapshot metadata (vectors, last hydration time).
    - Cache sizes (mappings, enrichment, parsing, mood vectors).
    - Feedback buffer statistics and opt-out counts.

- **Feedback buttons**

  - The Now Playing UI only displays “More Like This” / “Less Like This” when V2 is operational. If buttons disappear, V2 likely fell back to V1; verify availability.

- **Collaborative updates**
  - When sufficient telemetry is collected, regenerate embeddings:
    ```powershell
    python scripts/cf_train.py --input cache/music/telemetry/events.jsonl --output modules/music/Autoplay_Engine/v2/cache/collaborative_embeddings.json
    ```
  - Reload the bot or trigger the collaborative hydration hook to pick up the new snapshot.

## 4. Telemetry & Privacy

- Guild or user opt-out can be toggled via helper methods on `FeedbackManager` (surface through admin commands if desired).
- Telemetry records hashed IDs only; salts are unique per installation.
- Retention window is 365 days by default; adjust via `FeedbackManager` constructor if policy requires.

## 5. Cache Maintenance

Cache files live under `cache/music/`:

| File                            | Purpose                                     | TTL              |
| ------------------------------- | ------------------------------------------- | ---------------- |
| `mappings_v2.json`              | YouTube mapping cache                       | 360 days         |
| `enrichment_v2.json`            | Enrichment payloads (tags, moods, metadata) | 180 days         |
| `parsing_v2.json`               | Gemini track parses                         | 120 days         |
| `mood_vectors_v2.json`          | Mood/energy vectors                         | 180 days         |
| `collaborative_embeddings.json` | Collaborative snapshot                      | Until replaced   |
| `telemetry/events.jsonl`        | Rolling JSONL telemetry log                 | Operator-managed |

Use the cache manager’s `purge_expired()` (wire via scheduled task) if you want periodic cleanup; otherwise files are pruned lazily on read.

## 6. Troubleshooting

| Symptom                                            | Likely Cause                                                            | Resolution                                                                                        |
| -------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Autoplay falls back to V1, feedback buttons hidden | Missing `LASTFM_API_KEY` or Gemini key; exception logged during V2 init | Populate keys, restart bot. Check for `Autoplay V2 failed to initialize` log entries.             |
| Gemini quota exceeded                              | Too many enrichment requests                                            | Reduce usage, wait for daily reset, or supply additional API keys.                                |
| Poor recommendation variety                        | Collaborative snapshot stale or telemetry suppressed                    | Re-run `scripts/cf_train.py`; verify telemetry opt-outs.                                          |
| Frequent Pomice lookup failures                    | Lavalink node offline or credentials changed                            | Validate Lavalink configuration, restart node, confirm `LAVALINK_HOST/PASSWORD`.                  |
| Cache returning stale mappings                     | TTL exceeded or YouTube video removed                                   | Cache manager purges automatically; forcing a delete of the mapping key triggers a fresh resolve. |

## 7. Smoke Tests (Phase 3 follow-up)

A dedicated smoke test harness is still pending. Until it lands, you can manually sanity-check V2 against a Lavalink test node:

```powershell
# Pick a representative YouTube URL
python - <<'PY'
from modules.music.Autoplay_Engine.v2 import get_lastfm_autoplay_v2
from main import bot  # adjust to your bot bootstrap accessor

engine = get_lastfm_autoplay_v2(bot)
print('Engine available:', engine.is_available())
PY
```

Verify that `get_recommendations_for_track` returns at least one result when given a populated track payload pulled from a live queue entry.

## 8. Rollback Procedure

1. Set `AUTOPLAY_VERSION = "v1"` in `modules/music/Autoplay_Engine/config.py`.
2. Restart the bot process.
3. Confirm logs report `Autoplay Engine: Using version V1`.

Caches created by V2 are isolated (`*_v2.json`) and will not affect the legacy engine.
